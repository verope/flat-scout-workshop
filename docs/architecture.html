flat-scout · architecture

Listings in, grades out

One command takes a rental listing URL as far as a Verdict: the page is downloaded, its EPC and floorplan are read, every Criterion in the brief grades the flat on its own, and the grades are stored beside the sentence that explains each one. The interesting part is not the scores. It is the machinery around them for finding out whether a grader is doing any work at all, which is what a workshop on evaluating LLM systems needs to see.

01 — One command, one Listing

What check <url> does

Everything happens in one process against one SQLite file. The model is reached in exactly two places, both after the hard filters, so a Listing that was never going to qualify costs nothing. Every step that can fail records an event and leaves the row in a state the next run can pick up; nothing is silently dropped.

The image reading is stored on the row with a timestamp, so a retry after a model outage, a grade --backfill and a grade --measure all reuse it and pay for no vision call. A retry also never downloads the page again: the fetched fields are already on the row. Only the evaluation is repeated. Before the images are read they are cached once under data/images/<portal>_<id>/, with the path stored beside the URL, and the readers prefer the local file: after check nothing depends on the Portal’s media host.

02 — Two evaluators, one switch

One score you cannot argue with, or ten grades you can

Both evaluators read the same Listing and the same image reading. They differ in what the model is asked, how many times, and what you can learn when the answer is wrong. weighted_criteria in config.toml chooses.

The two paths score on different scales, so hopeful_threshold means something different under each. Switch the flag and set the threshold from a fresh report histogram; a threshold carried across is a number about the other evaluator.

03 — The unit of the brief

A Criterion is one file, and the file is the prompt

Front matter says how the Criterion is graded and how much it counts. The body is the rubric. For a model-graded Criterion the body is sent verbatim on every call, so every sentence in it is prompt weight: a note about the rubric's history belongs in the README, never here.

---
name: A tenancy that accepts a dog
description: Silence means unknown. A stated no-pets policy is a dealbreaker.
weight: 3
veto_at_or_below: 0
grade:
  model: true
unknown: skip
silence_prior: {0: 0.7, 10: 0.3}
ask: "What is the building's pet policy?"
---

## What this measures
Whether the tenancy will permit a dog.

## Rubric
**10** — an explicit pet-friendly policy at no extra cost.
**8** — pets stated as considered, or permitted on application.
**5** — pets mentioned with conditions or an added deposit.
**0** — a stated no-pets policy. This rejects the listing outright.

## Evidence, and what not to read into it
Very few listings say anything, and silence means unknown,
not no. Never reject on silence: return null.
grade
Exactly one of four forms. field + map looks a closed-set field up (an EPC band, a layout verdict); field + bands reads a number off thresholds; grader names a Python function for anything needing more than one field; model: true asks a model. The loader refuses a map that omits a value the field can take.
fallback: model
Try the field first; ask the model only when the field is absent. A floor area from the EPC certificate settles the size Criterion without a call; a Listing with no certificate goes to the model.
unknown
skip leaves an unanswered Criterion out of the Coverage and lets the scorer price it. A number supplies a default value instead: it moves the Score, never the Coverage, and can never fire a veto.
veto_at_or_below
A determined grade at or under this rejects the Listing outright. Only a fact can veto, which is why every Criterion carrying one also says unknown: skip.
silence_prior
What an advert's silence suggests, as odds over grades. Used only where a model read the advert and found nothing; a field nobody extracted is not silence.
ask
The question to put to the agent when this Criterion comes back unknown. A determined Criterion proposes nothing.
weight
How much the Criterion counts. Above zero, or the loader refuses it: a zero-weight Criterion still costs a call and still reads as active.

What the rubric hash covers

Every stored grade carries a fingerprint of the grade block, the fallback and the body. grade --backfill re-grades a Criterion only when the fingerprint on disk differs from the one stored. Deliberately not hashed: weight, unknown, veto_at_or_below, ask. Those are applied when a grade is read, so editing any of them leaves every stored grade valid and costs no model call. That is the whole of the tunability.

What no hash covers

Two things change what a grade would be without moving any fingerprint: the Python in graders.py and the shared preamble in _brief.md and _fields.md. After editing one of those, grade --backfill reports nothing stale while newly graded Listings quietly use the new text. The escape hatch is explicit: grade --backfill --force, scoped with --criterion.

04 — From grades to a Verdict

Silence is priced, never ignored

The Score is a weighted mean over the whole brief. A Criterion that came back unknown enters at unknown_prior (4 of 10) rather than being left out, because a mean over the answered Criteria only rewarded an advert for saying less: the flat that answered least scored highest. Coverage says how much of the brief could be read at all, and it moves the Score continuously rather than only gating it.

The weights are the ones shipped in criteria/. Then the Verdict, in this order: reject if any Criterion with a veto is determined at or under its line; hopeful if the Score reaches hopeful_threshold and the Coverage reaches coverage_floor; borderline otherwise. The reasons are the three highest-weighted grades above 5, the red flags are the vetoes, the coverage warning, every concern a grader raised, and the lowest grades below 5. A Listing where nothing at all was read has no Score rather than a Score made of prior: that would be a number about the brief, not the flat.

05 — The status machine

Every path ends somewhere

A row's status is the only thing the pipeline branches on. A Listing the Portal has withdrawn goes to a terminal state rather than a retry queue, because retrying cannot help. A download that fails four times stops. And a decision, once recorded with approve or reject, is final: a second one is logged and ignored.

An evaluated Listing is never evaluated twice. Every replay (grade --backfill, rescore, report --weights) writes to criterion_grades or to nothing at all; the Score and Verdict stored at evaluation time stay as they were, because they are the record your decision was taken against.

06 — Reading the images

Perception is the model’s job. Measurement is not.

Three things in the brief exist only inside pictures: the EPC band, whether the reception is a real room, and which way the windows face. The last one is where this pipeline earns its complexity. Asked for the aspect directly, a model reads the compass correctly and then rotates the plan wrongly, a confident wrong answer nobody can check without opening the floorplan. So the model is asked only for the one thing it does better than any measurement: where on the page the compass is. Everything after that is arithmetic in compass.py.

The two estimates of north have nothing in common, which is the point: a model assumes north is up on a compass it cannot see, while a measurement taken from a badly placed box confidently measures the wrong symbol. Requiring agreement is a far stronger guarantee than running either one twice, and it costs nothing extra, because the model has to locate the window walls anyway. On disagreement the aspect is null and the Criterion comes back unknown, which is the honest answer.

07 — Knowing whether a grader works

Three questions a rubric can be asked, and the command for each

A histogram of scores says how many Listings clear a line, never whether the ones above it are the ones a person would have wanted. No machine can say a rubric is right. It can say three narrower things, and each has its own tool.

Against ground truth

annotate serves a local page where a person writes down, for each floorplan in tests/fixtures/floorplans/, where the north indicator points and which walls the windows are on. Answers are in image terms, so the annotator does no arithmetic and the two pipeline stages can be scored apart.

benchmark runs the reader over every annotated plan and scores north, the window walls and the final aspects separately, each as right, wrong, abstained or correctly silent. Abstention is its own outcome: a plan with no compass drawn is answered correctly by saying nothing, and a pipeline that invents a bearing there is the failure the corpus exists to catch.

Against itself

grade --measure grades every model-reachable Criterion several times over the same Listings and reports two numbers per Criterion: how often it returned unknown, and the widest spread between its own answers on one flat.

A Criterion unknown on nine flats in ten is asking for something adverts never say. One that answers 2, 6 and 9 on the same flat has no anchors the model can find, and its weight is buying noise. Neither says the rubric is correct; both say whether it is doing any work.

Against your decisions

Record your own yes or no with approve and reject. Then report --weights prints, per Criterion, its mean grade among the Listings you approved against the ones you rejected. A Criterion whose separation is negative graded well exactly the flats you turned down: no weight rescues that, the rubric is what needs rewriting, and the report names the file.

The same command replays any candidate weighting over the stored grades with no model call, and says what it would have done to the flats already decided.

Retiring a Criterion is an experiment, not a deletion

Move the file into criteria/retired/. The loader reads criteria/*.md and does not recurse, so the Criterion stops counting at once, and its stored grades stay in the database untouched. Move it back and they are still valid, as long as the rubric was not edited while it was out: the hash decides, not the location.

What the hard filters hid

report --suppressed lists the Listings that were seen and never graded, counted by which filter fired. The count is the finding: a price cap accounting for nearly every row is a cap set below the market, and no amount of reading the individual rows will show it.

08 — Invariants

What isn’t written down as a rule but is in every module

Between them these explain most of what looks like over-engineering in a small tool. Each was learned from a wrong answer that nobody downstream could have caught.

Measurement, not modelcompass.py · aspect_from_bearings · render_reading

Wherever an answer can be computed, it is, and the model is never asked for it. The window aspect is derived from two bearings rather than requested; epc_band_source is set from the image that was actually sent; square metres become square feet in code. Perception is the model’s job. Arithmetic is not, and handing it over produces confident wrong answers of precisely the kind nobody downstream can catch.

Guarantees that don’t depend on compliance_only_what_was_seen · the loader

The prompt asks for a null band when the image is doubtful; _only_what_was_seen then erases any answer about an image that was never sent, whatever the prompt asked for. The loader refuses a map that omits a value the field can take, a zero weight, and a silence_prior on a Criterion no model reaches. A prompt is a request. A filter is a constraint.

Null beats a guessbedroom_has_window · floor_text · pin quality

Every field a vision model fills may be unknown, and unknown is the answer whenever the image is absent, unreadable or ambiguous. bedroom_has_window is False only for a plan that positively shows an internal bedroom. The floor printed on a plan is kept only when two independent reads agree word for word, after one read invented “Ground Floor” on a drawing that contains neither word. A portal pin that is not ACCURATE_POINT leaves the coordinates empty rather than placing the flat somewhere it is not.

Silence is priced, not ignoredunknown_prior · silence_prior · determined

“Absent means unknown, never bad” is the determined flag: an unread Criterion never fires a veto and never counts toward Coverage. But it is not dropped from the Score either, because a mean over the answered Criteria alone rewards an advert for saying less. It enters at a prior slightly below the middle, on the claim that an advert omits what does not flatter the flat.

One Criterion per callgrade_one · grade_listing · CachePoint

Isolation is the design: a Criterion knows nothing about the others, so a grade that is wrong is attributable to one rubric. The calls are independent by construction, which is what lets them run concurrently. One goes first alone, deliberately: the shared preamble and the Listing are marked cacheable, and the provider’s cache entry does not exist until the first response begins. Fanning all of them out at once turns every call into a cache write.

The rubric file is a promptcriteria/*.md · README

A model-graded Criterion’s body is sent on every call, so its history is prompt weight on every Listing, and telling a grader that its rubric does not discriminate is a hint it does not need. Anchor every level on something the advert said, never on its silence: a “5 for nothing either way” anchor turns an absence into a determined grade. Say unknown: skip and let it come back unknown.

Replays write nothing that a decision was taken onrescore · report --weights · backfill

An evaluated Listing is never evaluated twice, so an edited brief acts only on Listings that have not arrived yet. The replays exist to show what the edit would have done to the ones that have, and they leave the stored Score alone on purpose: overwriting it would silently rewrite the calibration data, so a flat approved at 8.0 would be compared against a decision taken on a number that no longer exists anywhere.

What it deliberately doesn’t do

  • Download a Zoopla page. Zoopla challenges every automated client, and the challenge is not worked around.
  • Contact anyone. Nothing here sends anything.
  • Merge cross-portal duplicates.

Watching it run

  • Every long command prints a progress bar, or a line every thirty seconds when there is no terminal.
  • With a LOGFIRE_TOKEN, every model call, image download and page fetch is a traced span carrying tokens, latency and the Criterion that asked. Without one, nothing is configured and nothing leaves the machine.

Switched off, still there

  • bayesian_verdict = false: the point Score and coverage_floor decide the Verdict. posterior.py and fit remain for anyone who wants the posterior gate back, where an unread Criterion widens the Score’s interval instead of tripping a floor.
